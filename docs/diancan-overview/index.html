大家好，今天我讲一个我做过的真实完整项目，叫 diancan-system，点餐系统。 完整复刻了一个中型餐饮门店从顾客扫码到后厨出餐的全流程业务。 整套系统包含三个子项目：Java 17 + Spring Boot 3.2 的后端、Vue 3 + Vite 7 的管理后台、以及原生微信小程序的顾客点餐端。 后端代码量大概 755 个源文件，数据库有 42 张业务表，按领域分成了 16 个业务模块——包括交易主链、支付、会员、优惠券、后厨履约、报表这些常见 SaaS 域。 技术上还集成了 RocketMQ 可靠消息、Redis 多实例广播 WebSocket、微信支付回调验签等一些生产级组件。 这个项目最大的价值是业务闭环：任何一处入口下单，都能完整跑通支付、履约、结算、营销。 接下来我会按 6 个维度讲清楚它：项目定位、技术栈、系统架构、后端模块地图、关键技术亮点、下一步扩展方向。 每页大约 3 分钟，有问题随时打断我。

为什么要做这个项目？三个目标。 第一，业务闭环：不是 demo，是真的把餐饮门店核心交易链路打通了——扫码入桌、点餐下单、支付结算、后厨打单、会员积分、报表导出——一条链路贯穿，而不是单点展示。 第二，工程规范：后端按 com.scaffold.modules.<domain> 分 16 个模块，每模块内分 controller、service、mapper、entity、dto、vo 五层；管理端和小程序 API 调用都集中在 src/service/api/ 和 api/——改一处必同步改另外一处。 第三，简历素材：它是一套生产级的项目，不是教学 demo。 代码里有真实的支付回调、商品规格组合、会员等级联动这些工程复杂度，能讲出技术深度。 所以我后面会逐项展开。

技术栈分三层。 后端用 Java 17 加 Spring Boot 3.2.5，ORM 选了 MyBatis-Plus，鉴权用 Sa-Token，消息队列用 Apache RocketMQ，对象存储用 MinIO，文档用 Knife4j。 选 MyBatis-Plus 而不是 MyBatis，是为了减少手写 XML；用 Sa-Token 而不是 Spring Security，是因为它对多终端、多角色场景更友好。 管理端用 Vue 3 加 Vite 7，TypeScript 是强制的——这点很多人懒省——状态用 Pinia，UI 用 Element Plus。 小程序端没用 uniapp 或 taro，是原生微信小程序——原生 API 调用最直接，没有跨端框架的封装税。 存储层：MySQL 做主库，Redis 缓存 Sa-Token 会话和热点菜品，RocketMQ 处理优惠券发放这种异步可靠消息，MinIO 存菜品图片。 这套组合没有奇技淫巧，全是 Java 后端 SaaS 的经典组合——面试官一打听就知道是生产实践而不是追新。

关键设计：三端共用一套 Spring Boot 服务和事务管理，但独立打包。无根 Docker Compose — 保留调试透明度。

架构图分三列。 最左边是管理端，Vue 3 SPA，单端口 9527，前端 Nginx 静态化打包。 中间是顾客端，原生微信小程序，没有 Web 框架。 最右边是后端，Spring Boot 单体，端口 8080，统一上下文 /api。 关键设计：后端在同一个服务里按域名分子路径——管理端走 /api/admin/*，顾客端走 /api/app/*，支付回调走 /api/wx/pay/**——这样三个客户端各自打包，却共用一套业务代码和事务管理。 反向问题：为什么没有根 Docker Compose？因为这个仓库手工协调三个子项目，每个独立启动，没有根编排器。 面试官如果问部署方案，我会说生产用 Kubernetes + Helm，但当前版本为了调试透明度保留了手工启动——这是个 trade-off。

// deep-dive · 08

四个关键技术亮点。

01

RocketMQ 可靠消息

本地消息表 + 定时重试 + 人工补偿队列。优惠券异步发放、过期回收都走这套。这是分布式事务的常见解法，叫本地消息表。

02

WebSocket 多实例广播

WsService 发到 ws:channel:*，RedisMessageSubscriber 广播到客户端——多实例部署无粘性。

03

多支付集成

PaymentServiceImpl 统一抽象微信支付、支付宝、现金、AA 制、分账五种通道 + BouncyCastle 验签。

04

Sa-Token RBAC

StpInterfaceImpl 加载权限，RolePermissionDefaults 默认映射。公开接口白名单走 PUBLIC_PATHS。

面试时直接甩这套
四个关键技术亮点，每个都是面试的 hook。 第一个：RocketMQ 可靠消息。 优惠券发放走异步消息——MqService 把消息先持久化到本地数据库，再投递到 RocketMQ。 消息表里有 ack 字段，超过一段时间没 ack 就重试，重试多次失败进入人工补偿队列。 这是分布式事务的常见解法，叫 本地消息表——面试官问分布式事务，直接甩这个。 第二个：WebSocket 多实例广播。 门店点单、后厨打单这类实时消息用 WebSocket。 多个后端实例之间用 Redis Pub/Sub 中转，WsService 发到 ws:channel:*，RedisMessageSubscriber 广播给客户端——避免粘性问题。 第三个：多支付集成。 微信支付、支付宝、现金、AA 制、分账——五种支付方式在 PaymentServiceImpl 统一抽象。 第四个：Sa-Token RBAC。 StpInterfaceImpl 加载用户权限，RolePermissionDefaults默认权限映射——这是生产级 SaaS 的标准模式。
